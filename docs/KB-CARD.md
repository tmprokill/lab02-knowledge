## 2. Призначення
- **Предметна область:** Архітектура, патерни надійності, життєвий цикл договорів та фінансово-експлуатаційні регламенти модульної платформи управління нерухомістю SmartLease (.NET 10, PostgreSQL).
- **Зв'язок із кваліфікаційною роботою:** Тема кваліфікаційної роботи здобувача: «Корпоративна платформа управління орендою комерційної та житлової нерухомості SmartLease». База знань містить системну документацію доменних модулів Properties, Maintenance, Finance, Utilities та архітектурного ядра.
- **На які питання відповідає (3 приклади):**
  1. *«Які обов'язкові умови та строки повернення гарантійного страхового депозиту при виїзді орендаря?»*
  2. *«Як патерн Transactional Outbox запобігає втраті доменних подій активації договору оренди в PostgreSQL?»*
  3. *«Які часові нормативи реакції встановлені регламентом SLA для аварійних заявок Emergency?»*
- **На які питання НЕ відповідає (межі):**
  - Не містить персональних даних мешканців, банківських паролів, секретних ключів API та токенів автентифікації.
  - Не відповідає на сторонні питання, що не стосуються архітектури та правил платформи SmartLease (наприклад, криптовалюти, блокчейн чи сторонні фреймворки — агент штатно повертає `NOT_FOUND`).

## 4. Індекс
- **Модель ембедингів / розмірність:** `gemini-embedding-001` / 3072 виміри (з префіксами `[retrieval_document]` та `[retrieval_query]`).
- **Метрика:** Косинусна відстань (`hnsw:space: cosine`).
- **Параметри чанкінгу:** `chunk_chars = 700`, `overlap = 80`, розбиття за заголовками другого рівня (`##`).
- **Параметри пошуку:** `top_k = 4`, калібрований поріг `KB_MAX_DISTANCE = 0.28`.
- **Режим Chroma:** `PersistentClient` (локальне збереження у `./chroma_data`) та підтримка клієнт-серверного `HttpClient` через `CHROMA_HOST` (Крок 14).

## 5. Якість пошуку
- **Контрольний набір:** 12 запитів (10 цільових у базі, 2 поза базою).
- **hit@4:** 1.000 (10/10 цільових документів знайдено на 1-й позиції).
- **MRR (Mean Reciprocal Rank):** 1.000.
- **Хибні прийняття (False Accepts):** 0 при каліброваному порозі `0.28` (100% специфічність на позадоменних запитах).

## 6. Агент
- **Дії:** `search_knowledge`, `read_note`, `write_note`, `finish`.
- **Ліміти:** `MAX_STEPS = 6`, `MAX_LLM_CALLS = 8`.
- **Результати експерименту (правильність 0-2, середнє):**
  - One-shot LLM: 1.0 / 2.0 (страждає від галюцинацій на неіснуючих об'єктах);
  - Наївний RAG: 1.6 / 2.0 (помиляється на складних питаннях синтезу багатьох нотаток);
  - KB-Агент: 2.0 / 2.0 (абсолютна точність, гнучкий багатокроковий пошук та цитування).
- **Обґрунтованість (частка дійсних посилань):**
  - Наївний RAG: 0.0% (відсутні посилання у форматі Obsidian);
  - KB-Агент: 100.0% (усі посилання `[[Нотатка#Розділ]]` верифіковані утилітою `eval.citations`).

## 7. Безпека і обмеження
- **Дані, що не включаються до сховища:** Персональні дані орендарів, паролі, секрети та приватні ключі API.
- **Захист від непрямої ін'єкції (Indirect Prompt Injection):** Суворі інструкції системного промпта, що трактують тексти нотаток як пасивні дані, а не виконувані директиви; заборона ігнорування системних правил; валідація дій.
- **Захист від Path Traversal:** Примусова перевірка відносного шляху у `read_note` через `Path.relative_to(vault_path)`.
- **Human-in-the-loop (`write_note`):** Запис дозволено виключно в папку `Inbox/` і тільки після явного інтерактивного підтвердження людиною в консолі.
